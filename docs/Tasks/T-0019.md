# T-0019: App tiles show why an App is in warning or error

**Status:** [DONE]
**Branch:** `task-T-0019-tile-status-reasons`
**Created:** 2026-10-16

## Context

A dashboard App tile shows a `🟡 Warning` / `❌ Error` badge but not *why*. The backend already
computes the reason: `/api/apps` returns `overall_status_detail` per App (the Health Check
`message`, or a platform reason such as `systemd unit failed`, `/health unreachable`,
`starting`, or `runtime_info.error_message`). The tile never renders it. The only reasons
shown today are ad-hoc alerts on Service App tiles (DB provisioning failed, unmet deps,
registry `error_message`), and the `error_message` alert duplicates `overall_status_detail`
when both are set.

## Plan

- [x] `templates/dashboard.html`: one `buildStatusReasons(app)` helper that collects every
      known reason — `overall_status_detail`, DB provisioning failed, unmet deps,
      `runtime_info.error_message` — de-duplicated, and renders them as a list under the
      status badge. `overall_status_detail` is only added when the displayed status is
      warning/yellow or error/red (on green/grey it just says `healthy`/`stopped`). The DB
      and unmet-deps alerts are kept on every tile, as `buildErrorAlerts` did — they are real
      problems even when the badge is green. Text colour follows the badge (amber for
      warning, red otherwise).
- [x] Use it on both Service App and Streamlit App tiles; replaces `buildErrorAlerts`.
      Streamlit tiles gain the DB/deps alerts they never showed before.
- [x] HTML-escape every reason (Health Check messages are App-supplied text rendered via
      `innerHTML`).
- No backend change, no Manifest or `/health` contract change.

Promotion triggers: dashboard template only — one subsystem, no schema, no new service,
one scope. Stays a Task.

## Acceptance

- **t19-001:** App whose `/health` returns `warning` with message `"Disk 91% full"` → tile
  shows the Warning badge and the text `Disk 91% full` below it.
- **t19-002:** App whose `/health` returns `error` with message `"Upstream API down"` → tile
  shows the Error badge and `Upstream API down`.
- **t19-003:** App in error with `error_message` equal to `overall_status_detail` → the
  reason appears once, not twice.
- **t19-004:** App in error with unmet deps and a detail → both reasons are listed.
- **t19-005:** Green or grey (stopped) App with no DB/deps problem → no reasons block.
- **t19-006:** Reason containing `<b>x</b>` → rendered as literal text, not HTML.
- **t19-007:** Unit suite still green: `PYTHONPATH=src python3 -m pytest tests/ -q`.
