# T-0017: TST serves on its own domain at the standard HTTPS port

**Status:** [DONE]
**Branch:** `task-T-0017-tst-domain-443`
**Created:** 2026-10-16

## Context

The operator changed the homeserver deploy: Latarnia TST now has its own hostname,
`home-tst.stanham.com` (A record, not the tplinkdns CNAME), and is meant to be reached at the
standard HTTPS port. `CaddyConfigManager._site_address()` still hardcodes TST to
`{TST_DOMAIN}:8443`, so the generated include never claims `home-tst.stanham.com:443` and Caddy
answers that SNI with a TLS internal-error alert.

Since TST and PRD no longer share a hostname, both can sit on `:443` — Caddy picks the site by
SNI/Host. The `:8443` split only existed so the two envs could share `home.stanham.com`.

## Plan

- [x] `_site_address()`: TST → `{domain}:443` (same as PRD); update docstring.
- [x] Unit test: TST site address asserts `:443`.
- [x] `.env.example`: `TST_DOMAIN=home-tst.stanham.com`, comment reflects both envs on `:443`.
- [x] Living docs (`docs/System/architecture.md`, `docs/local/deployment.md`) drop `:8443`.
      Closed project/task records (P-0008, P-0010, T-0003, T-0005) stay as historical record.

Out of scope (operator, host-side): setting `TST_DOMAIN=home-tst.stanham.com` in the
`latarnia-tst.service` environment, and closing `ufw` 8443 once nothing listens there.

## Acceptance

- **t17-001:** `CaddyConfigManager` with `env=tst`, `TST_DOMAIN=home-tst.stanham.com` → generated include contains `home-tst.stanham.com:443 {` and no `8443`.
- **t17-002:** `env=prd`, `PRD_DOMAIN=home.stanham.com` → still `home.stanham.com:443 {`.
- **t17-003:** Full unit + integration suite green (`PYTHONPATH=src python3 -m pytest tests/ -q`).

## Result

All acceptance executed and green: `test_tst_site_address_uses_own_domain_443` (t17-001),
`test_prd_site_address_uses_domain_443` (t17-002), full suite 486 passed / 1 skipped (t17-003).

**Before promoting to `tst`:** the `latarnia-tst.service` environment must carry
`TST_DOMAIN=home-tst.stanham.com`. If TST and PRD share a domain on one host, both includes
define the same `{domain}:443` site and Caddy rejects the whole config.
