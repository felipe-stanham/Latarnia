# T-0023: Per-App authorization — `/auth/verify` rejects role `none`; UI API proxy checks access and forwards identity

**Created:** 2026-11-23 | **Status:** [IN PROGRESS] | **Origin pitch:** none
**Branch:** `task-T-0023-per-app-authz` | **Base:** `dev`
**Related:** [I-0002](../Pitches/I-0002.md) App REST API. Found while mapping how each entry point authorizes calls
to an App. Both gaps exist today, independent of I-0002.

## Context

The platform authenticates and resolves the caller's per-App role; the App decides what each role may do. Two
entry points skip the per-App part:

1. **`/auth/verify` lets role `none` through.** `verify` in `src/latarnia/auth/routes.py` returns 200 for any valid
   session and only *reports* `X-Latarnia-App-Role: none`. An App that ignores the header (latarnik does) serves its
   web UI and its whole `/api/*` (writes included) to every logged-in user, even with role `none` on that App.
   The dashboard tile is hidden, but the URL works.
2. **The UI API proxy has no per-App check and sends no identity.** `/api/apps/{app_id}/ui/resources`,
   `/api/apps/{app_id}/ui/{resource}` and `/api/apps/{app_id}/ui/{resource}/{item_id}` in `src/latarnia/main.py`
   only pass the `/api/*` authentication gate. Any session user — or a Machine Token scoped to a different App —
   reads any App's UI API resources. The platform then calls the App's port with no `X-Latarnia-*` headers, so the
   App cannot tell who is asking.

**Amendment 2026-11-23 (code review BLOCK-1).** Gap 1 has a second cause: inside `handle_path /apps/{name}/*` Caddy
strips the prefix *before* `forward_auth` runs, and `forward_auth` sends `X-Forwarded-Uri: {http.request.uri}` — the
stripped URI. So `/auth/verify` sees `/page`, not `/apps/{name}/page`, cannot tell which App is asked, and computes
role `none` for every non-superuser on every App web UI (an undetected P-0008 bug: per-App roles never reached any App
web UI). Every existing test set `X-Forwarded-Uri: /apps/...` by hand and never went through Caddy. Fix: send the
original URI (`{http.request.orig_uri}`, the same fix P-0010 used for the login redirect), normalize it before reading
the App name, and add tests that run the real chain Caddy → `/auth/verify` → App so this class of bug cannot come back.

## Goal

The platform denies a caller whose role on an App is `none` at every browser entry point to that App, and the UI API
proxy forwards the caller's identity and per-App role to the App, exactly as Caddy does for the web UI.

## Touches

- `src/latarnia/auth/routes.py` — `verify`: return 403 when the forwarded path is `/apps/{app}/*` and the effective
  role is `none`.
- `src/latarnia/main.py` — one helper that resolves the caller's access to an App (Machine Token claims or session)
  and returns the identity headers, raising 401/403 otherwise; used by `get_app` (replacing its inline branch) and
  by the three UI API proxy endpoints.
- `src/latarnia/web/ui_renderer.py` — `discover_ui_resources`, `fetch_resource_list`, `fetch_resource_detail`
  accept an optional `headers` dict and send it on the request to the App.
- `examples/example_full_app/app.py` + its `/ui` list — a `caller` UI API resource that echoes the received
  identity headers, so the fixture exercises the forwarding end to end.
- `src/latarnia/caddy/manager.py` — `_forward_auth_lines`: `header_up X-Forwarded-Uri {http.request.orig_uri}` inside
  the `forward_auth` block (applies to every `/apps/{name}/*` block and the catch-all).
- `src/latarnia/auth/routes.py` — `_extract_app_name`: normalize the path (`posixpath.normpath` after dropping the query
  string) before taking the App name.
- `tests/unit/test_machine_token_access.py`, `tests/integration/test_auth_flow.py`, `tests/unit/test_caddy_manager.py` —
  new cases (below).
- `tests/integration/test_caddy_forward_auth.py` (new) — runs the real `caddy` binary with a Caddyfile produced by
  `CaddyConfigManager` in front of the real auth router and a stub App; asserts what verify and the App actually receive.
- `TESTS.md` — fix `test_verify_headers` wording; add the live regression entries below.
- `tests/cache/regression_live.sh` — live checks through the public ingress on tst (role `none` → 403; role reaches
  the App web UI).
- `docs/System/app-specification.md` — "Authentication Headers": `none` is now rejected by the platform; UI API
  calls from the dashboard carry the same headers. (Updated by `doc-updater` in step 6.)
- **Pattern reference:** `get_app` in `src/latarnia/main.py` (T-0022 claims-vs-session branching, 401/403 messages);
  `/b/test` in `examples/example_full_app/app.py` (header echo).

## Tasks

- [ ] `verify`: after resolving the user and `app_name`, if `app_name` is not `None` and the effective role is
      `none` (superuser is always `full`), return `Response(status_code=403, content="No access to this app")`
      with no `X-Latarnia-*` headers. Non-App paths (`app_name is None`: dashboard, `/docs`, …) keep today's
      behaviour.
- [ ] `main.py`: add `_app_access_headers(request, app_name) -> dict` implementing exactly `get_app`'s rule —
      JWT claims present: super → role `full`; else role = `claims["apps"].get(app_name, "none")`, `none` → 403
      "Token not scoped to this app"; no claims: session user or 401 "Authentication required", superuser → `full`,
      else `role_store.get_role`, `none` → 403 "No access to this app". Returns
      `{"X-Latarnia-User": <user id / claims["sub"]>, "X-Latarnia-App-Role": <role>, "X-Latarnia-Is-Super": "true"|"false"}`.
- [ ] `get_app`: use the helper (behaviour unchanged; T-0022 tests stay green).
- [ ] The three UI API proxy endpoints: take `request: Request`; after the 404 "App not found" check, call the
      helper with `app.name`; pass the returned headers to `ui_renderer`. No request reaches the App on 401/403.
- [ ] `ui_renderer`: the three fetch methods take `headers: Optional[dict] = None` and pass it to `httpx`.
- [ ] `example_full_app`: add `"caller"` to `/ui`; add `GET /api/caller` returning
      `[{"id": 1, "user": <X-Latarnia-User>, "role": <X-Latarnia-App-Role>, "is_super": <X-Latarnia-Is-Super>}]`
      (missing headers → `null`).
- [ ] `CaddyConfigManager._forward_auth_lines`: add `header_up X-Forwarded-Uri {http.request.orig_uri}` inside the
      `forward_auth` block. Keep the 401-only redirect unchanged.
- [ ] `_extract_app_name`: drop the query, `posixpath.normpath` the path, then read `apps/{name}`. A path that
      normalizes out of `/apps/` (e.g. `/apps/../x`) returns `None` only if the result is not under `/apps/`.
- [ ] Use the existing `H_USER` / `H_ROLE` / `H_SUPER` constants from `auth/routes.py` in `main.py` instead of string
      literals.
- [ ] `example_full_app`: add `GET /api/caller/{item_id}` returning the same dict (the dashboard detail modal calls it).
- [ ] Real-chain test `tests/integration/test_caddy_forward_auth.py`: generate the Caddyfile with `CaddyConfigManager`
      for one web-UI App, pointing at a local uvicorn running the real auth router (session + RoleStore, same fixture
      style as `test_auth_flow.py`) and a stub App that echoes the `X-Latarnia-*` headers it receives. Start `caddy run`
      on free localhost ports (HTTP only, no TLS/ACME), then drive requests through Caddy. If the `caddy` binary is not
      on PATH the module skips with the reason `caddy binary not installed — real-chain auth tests NOT run` (loud,
      explicit). Postgres-unreachable skip as in `test_auth_flow.py`.
- [ ] `TESTS.md`: reword `test_verify_headers`; add the live entries `test_live_none_role_blocked_at_ingress` and

- [ ] Unit + integration tests for the acceptance criteria below.
