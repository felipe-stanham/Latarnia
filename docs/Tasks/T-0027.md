# T-0027: Health monitor probes every running Service App

**Created:** 2026-11-25 | **Status:** [ ] Not Started | **Origin pitch:** none

**Related:** pre-tst docs audit (code-suspect B2). The user decided the code is wrong.

## Context

`HealthMonitor._perform_health_checks` (`src/latarnia/managers/health_monitor.py` ~160-175) only checks Service Apps
whose Manifest sets `config.has_UI: true`. Every Service App must implement `/health` (glossary: Health Check), but a
Service App without a UI (e.g. `example_companion`) is never probed: its overall status stays unknown, it gets no
automatic restart after repeated failures, and its MCP liveness probe (`_probe_mcp_health`) never runs.

## Goal

The Health Monitor sends a Health Check to every running Service App, with or without a UI.

## Touches

- `src/latarnia/managers/health_monitor.py` — drop the `has_UI` condition from the checkable-app filter.
- `tests/unit/` — cases below (pattern: existing health monitor / `tests/unit/test_mcp_health_probe.py` tests).
- `docs/SYSTEM.md`, `docs/System/app-specification.md`, `docs/System/workflows.md` — remove the "known limitation"
  notes (doc-updater, step 6).
- **Pattern reference:** `tests/unit/test_mcp_health_probe.py`.

## Acceptance Criteria

- **t27-001:** Registry with a RUNNING Service App with `has_UI: false` → `_perform_health_checks()` calls
  `_check_app_health` for it.
- **t27-002:** Same with `has_UI: true` → still checked (unchanged).
- **t27-003:** A Streamlit App, a STOPPED Service App, and an ERROR Service App with no live process → not checked
  (unchanged).
- **t27-004:** A RUNNING MCP-enabled Service App with `has_UI: false` and a `good` `/health` → `_probe_mcp_health` runs
  for it.
- **t27-005:** Full suite green on ENV=dev.

## OUT of Scope / No-gos
