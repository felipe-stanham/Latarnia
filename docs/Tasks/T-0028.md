# T-0028: MCP Tool Index includes running Apps after a platform restart

**Created:** 2026-11-26 | **Status:** [ ] Not Started | **Origin pitch:** none
**Branch:** `task-T-0028-mcp-index-startup-sync` | **Base:** `dev`
**Related:** pre-tst docs audit (code-suspect). The user decided it is a bug; it does not block tst.

## Context

At platform startup (`src/latarnia/main.py` lifespan, MCP gateway block) the gateway calls `on_app_started` only for Apps
whose `mcp_info.healthy` is already True, and `MCPGateway._build_tool_index` (`src/latarnia/managers/mcp_gateway.py`
~133) applies the same filter. `MCPInfo.healthy` defaults to False and is set True only by `on_app_started` itself or by
`HealthMonitor._probe_mcp_health`, which runs later and does not sync the index. So after a platform restart, MCP-enabled
Apps that were auto-started or reconciled (e.g. Latarnik) are missing from the Tool Index until restarted through the API.

## Goal

After a platform restart, every running MCP-enabled App whose MCP server answers appears in the Tool Index without
being restarted.

## Touches

- `src/latarnia/managers/health_monitor.py` — when `_probe_mcp_health` flips an App's `mcp_info.healthy` from False to
  True, call the MCP Gateway's `on_app_started(app_id)` (inject the gateway the same way other managers are wired).
- `src/latarnia/main.py` — wiring only, if the health monitor needs the gateway reference.
- `tests/unit/test_mcp_health_probe.py` — cases below.
- `docs/System/workflows.md`, `docs/System/architecture.md` — remove the T-0028 known-limitation notes (doc-updater).
- **Pattern reference:** `tests/unit/test_mcp_health_probe.py`; how `main.py` passes managers to `HealthMonitor`.

## Tasks

- **t28-003:** Probe fails → `healthy=False`, `on_app_started` not called (existing failure handling unchanged).
